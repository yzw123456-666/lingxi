# 灵犀 (LingXi) v0.2

**一台从零发明的上下文混合无损压缩器。**
名字取自"心有灵犀一点通"——它的全部本事，就是在你写下下一个比特之前，猜中它。

---

## 0. 摘要（TL;DR）

- **发明**：灵犀是一个**单遍、在线学习、无预训练**的通用无损压缩器。它不找重复串（LZ 家族的思路），而是为每一个待编码的比特动态召集 16 路异构预测器投票，由可学习的混合器合成最终概率，再经三级概率精修与区间编码把概率变成比特。预测得越准，输出越短。
- **战绩**（18MB 六类语料，对方全部最高强度）：**1.095 bpc**，总输出比最强主流工具（xz -9e）再省 **26.2%**；六个文件中五个绝对第一，唯一惜败的是 19KB 中文散文（比 bzip2 多 35 字节，0.45%）。所有结果经过无损自校验 + 313 项模糊测试。
- **诚实的边界**：灵犀属于上下文混合（Context Mixing）家族——当今世界绝对纪录保持者（LTCB 榜单的 cmix / PAQ 系列）也属于这个家族。灵犀 v0.2 用 554 行 C 达到了超过 lpaq 量级的成绩，但尚未超越 cmix 那种 GPU 长时间训练的神经集成；路线图见 §7。

## 1. 原理：压缩即预测

香农 1948 年证明了：最优压缩器等价于最优预测器。若符号出现概率是 p，理论上最少只需 −log₂p 个比特。**压缩率分水岭从来不在熵编码器（各家早已旗鼓相当），而在预测器。**

主流工具的预测是"找重复"（LZ77）：gzip/zstd/xz/brotli 全部在历史里找相似串。它们只能利用**精确重复**。

灵犀的预测是"统计直觉"：编码到任意位置时，16 路异构预测器同时发言：

```
              ┌─────────────────── 感知层（16 路异构预测器）────────────────────┐
  多尺度情景记忆│  0/1/2/3/4/6/8/12 阶字节上下文（当前字节已编码高位并入键值）        │
  稀疏跳跃记忆  │  (c3,c1) (c4,c2)：跳过相邻字节，抗插入噪声                        │
  词法感知     │  当前单词哈希 + 词对哈希（前一词+当前词）                           │
  间接情景记忆  │  "这个上下文历史上后继的字节"本身再作上下文（二阶记忆）               │
  行列模型     │  上一行同一列的字节（源码缩进 / 日志对齐的克星）                     │
  长程匹配器   │  6 字节哈希定位历史同文，匹配越长发言越自信                          │
  运行模型     │  连续重复字节                                                    │
              └──────────────────────────────┬─────────────────────────────────┘
                                             │ 16 个对数几率域投票
                                             ▼
  决策层: 学习型混合器 — 2×256 组权重（按"长程匹配是否进行中"分裂 × 位前缀 c0），
          逻辑斯蒂混合 + 在线梯度下降（编码器/解码器同步，单遍，零预训练）
                                             ▼
  精修层: 三级 APM/SSE（c0 / hash(c1,c0) / hash(c2,c0) 各自按(预测,上下文)纠偏）
          + 学习式终混器: [主混合, 三路APM, 恒定] 由第四个小型混合器在线学习合成
                                             ▼
  写码层: 12 位区间编码器（LZMA 式进位传播，渐进溢出安全）
```

**关键洞察**：没有任何单一路径是孤立奇点——**发明在于这台机器的组织方式**：异构记忆的分工、冲突感知的双路哈希、按匹配状态分裂的权重、可学习的终混，共同构成一个边压缩边自我训练的预测系统。

## 2. 四项核心技术

### 2.1 双路关联哈希情景记忆（v0.2 最大单点改进，-5.8%）

每个哈希上下文映射到"桶 + 8 位校验码"，每桶 2 个候选单元：校验码匹配才使用，否则**确定性地替换置信度最低者**。直接映射表的冲突污染在 v0.1 中掩盖了大量信息——修掉它之后代码/二进制成绩立刻改善 11~12%。计数器 Cell 交错布局（概率+置信度同一缓存行）。

### 2.2 学习型混合器 + 匹配状态分裂

权重不是一组，而是 **2（常规/匹配中）× 256（位前缀 c0）组**。字节首比特与末比特、匹配进行与静止，面对的统计结构不同，各用各的专家。梯度下降在线进行，编码器与解码器执行**完全相同**的更新——所以文件里不需要携带任何模型。

### 2.3 三级 APM + 学习式终混

主混合输出依次经过三个自适应概率图（上下文递增：c0 → c1+c0 → c2+c0）纠偏，最后由一个 5 输入小型混合器在线学习"该信谁"（-1.6%，且显著改善了小文件表现）。

### 2.4 长程匹配器 + 区间编码器

6 字节哈希定位历史同文，匹配每延长一字节置信度 +MSTEP（终扫定值 16/1344 基准）。最终概率以 12 位定点送入 LZMA 式进位传播区间编码器。

## 3. 工程实现

- **单文件 C，554 行，零依赖**。`python -m ziglang cc -O2 lingxi.c -o lingxi.exe`（任意 C 编译器均可）。
- 内存约 110 MB（哈希表 + 双匹配/间接索引 + 三级 APM + 历史）。
- 文件格式：`"LX1" + 8字节原始长度 + 4字节 CRC32 + 编码流`。
- **无损性**：内置 CRC32 + 313 项外部模糊测试（0~300 每个尺寸随机数据、1MB 随机块、全零、全 0xFF、交替、UTF-8 混合、300K 单字节重复……全部逐字节还原）。

## 4. 使用

```bash
python -m ziglang cc -O2 lingxi.c -o lingxi.exe   # 编译（或任意 C 编译器）
./lingxi.exe c input output     # 压缩
./lingxi.exe d input output     # 解压（自动 CRC 校验）
```

## 7. 诚实声明与通往 cmix 的路线图

世界绝对前沿（Large Text Compression Benchmark）：cmix 在 enwik8 约 14.8 MB，PAQ 变体约 16 MB，lpaq 约 19.7 MB，xz 约 24.8 MB。灵犀 v0.2 的架构与实测成绩已越过 lpaq 量级；与 cmix 的差距主要在：

1. **更多模型**（cmix 上百个）：灵犀架构已验证"加模型→实测→留强汰弱"流程（§5.4），列模型、图像/PCM 专用模型、更多稀疏组合均为纯增量工作。
2. **两级混合器**：在 13 路规模下实测为负（实验 2），但模型数上到 30+ 后层级化预计转正——届时重测。
3. **神经先验**（NNCP/cmix 路线）：LSTM/Transformer 的下一比特预测作为混合器一路输入。灵犀的"零预训练、单遍在线"哲学与之正交，可混合。
4. **工程化**：SIMD/多线程（预期 5~10× 速度）、内存档位可调、分块随机访问。
